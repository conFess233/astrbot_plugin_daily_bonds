适用于接入 AstrBot 的 QQ 群。管理员可使用内置角色池，也可上传自己的角色图片、调整群规则和回复文案。

## 核心亮点

| 能力         | 说明                                                               |
| ------------ | ------------------------------------------------------------------ |
| 三种每日玩法 | 今日老婆、今日老公、娶群友，支持抢夺、赠送和离婚。                 |
| 指定角色     | 使用独立次数与保护槽位，支持配置角色独占或多人共享。               |
| 群友统计     | 亲密度、活跃度及活跃天数排行，可查询双方好感度。                   |
| 角色管理     | 内置《鸣潮》《战双帕弥什》角色池，支持批量导入图片和仓库配置同步。 |
| 群级配置     | 按群调整玩法、角色池、文案和回复引用，未覆盖字段继承全局配置。     |

<a id="quick-start"></a>

## 快速开始

运行要求：**AstrBot >= 4.28.2**，使用 **aiocqhttp** 适配器接入 QQ 群。娶群友需要 OneBot 端能够获取群成员名单。

1. 在 AstrBot Dashboard 插件市场安装，或通过仓库地址安装：`https://github.com/conFess233/astrbot_plugin_daily_bonds`。
2. 确认插件加载成功，保留宿主开关 `enabled=true` 和全局业务开关 `settings.enabled=true`。群准入默认不限制；已有配置启用了名单时，需允许测试群参与。
3. 在 QQ 群发送 `娶群友`。有合格候选时会回复群友名称，用于确认消息链路正常。
4. 发送 `今日老婆` 或 `今日老公`。首次启动会建立内置目录并在后台下载图片；取得图片时附图，图片不可用时可能只返回文字。

默认只启用鸣潮老婆池和老公池。要使用战双角色，在管理页的玩法配置中启用对应角色池。部分内置角色因缺少适合的素材而默认停用，可在角色目录补图后启用。

<details>
<summary>手动安装与依赖</summary>

在 AstrBot 安装目录执行，依赖必须安装到 **AstrBot 实际使用的 Python 环境**：

```bash
cd data/plugins
git clone https://github.com/conFess233/astrbot_plugin_daily_bonds.git

python -m pip install -r requirements.txt
```

依赖包括 aiohttp、Pillow 和 tzdata，版本约束见 [requirements.txt](./requirements.txt)。安装后在 Dashboard 插件页重载插件；加载失败时查看日志并从失败列表重新加载。Docker 部署需在 AstrBot 容器或实际运行环境中完成安装。

## 使用方法

以下为默认关键词，可在配置中修改。`<参数>` 表示必填，`[参数]` 表示可选，实际输入不包含括号。`@用户` 必须通过 QQ 选择成员，形成真实 At 消息段；手动输入 `@名字` 文本无效。

默认接受裸关键词、宿主命令前缀和开头 @ 机器人，未识别的聊天不回复。通用指令冷却为 3 秒。

### 抽取与关系操作

| 关键词                                                                | 作用                                                         |
| --------------------------------------------------------------------- | ------------------------------------------------------------ |
| `今日老婆` / `今日老公` / `娶群友`                                    | 从启用角色池或当前合格群成员中随机抽取。                     |
| `今日老婆 <名称或ID>` / `今日老公 <名称或ID>`                         | 指定角色，消耗独立指定次数，进入保护槽位。                   |
| `抢老婆 @持有者 [名称或#ID]` / `抢老公 @持有者 [名称或#ID]`           | 抢夺目标的关系，省略对象时随机选择；At 也可放在关键词前。    |
| `抢群友 @持有者 [QQ号]`                                               | 抢夺目标的群友关系，省略配偶 QQ 号时随机选择。               |
| `送老婆 @接收者 [名称或#ID]` / `送老公 @接收者 [名称或#ID]`           | 赠送自己持有的普通关系。                                     |
| `送群友 @接收者 [QQ号]`                                               | 赠送自己的普通群友关系。                                     |
| `离婚 [名称、#ID、QQ号或@成员]`                                       | 解除自己的普通关系，只有一段可解除关系时可省略目标。         |
| `离婚老婆 [名称或#ID]` / `离婚老公 [名称或#ID]`                       | 限定角色玩法；多段关系时需指定目标。                         |
| `离婚群友 [@成员、QQ号或完整名称]` / `踹群友 [同样参数]`              | 解除群友关系，不会将对方踢出群；可使用结婚时或当前成员名称。 |
| `接受赠送 [邀请编号]` / `拒绝赠送 [邀请编号]` / `取消赠送 [邀请编号]` | 处理确认模式的赠送；有多条待处理邀请时必须填编号。           |

指定抽取精确匹配当前玩法池内的角色名称、别名、原始 ID 或 `#ID`，ID 优先；角色需启用且已有登记图片。同名或别名歧义会列出候选，请改用明确 ID。离婚只查本人在本群当前周期的关系，跨玩法或同名歧义时需明确玩法和目标。

<details>
<summary>次数、槽位与关系保护规则</summary>

| 槽位 | 默认上限          | 次数与保护                                                           |
| ---- | ----------------- | -------------------------------------------------------------------- |
| 普通 | 每种玩法 1 个     | 每周期普通抽取总额度等于持有容量；成功离婚获得一次补抽资格。         |
| 抢夺 | 每种玩法 1 个     | 成功抢夺不占普通容量；槽位满时不扣抢夺次数、不进入抢夺冷却。         |
| 指定 | 老婆、老公各 1 个 | 槽位上限与每周期指定次数共用配置，成功才扣次数，不占普通或抢夺槽位。 |

- 抢夺和指定槽位的关系不能主动离婚、赠送或再被抢，只能等待周期重置；管理员纠错和参与资格变化仍可结束关系。结束指定关系不退指定次数。
- 抢夺默认成功率 30%，每周期最多尝试 3 次，冷却 60 秒；有效尝试失败也计入次数。抢夺槽位设为 `0` 时使用普通容量规则。
- 指定额度设为 `0` 时关闭指定功能。指定独占默认开启，角色已有关系则拒绝；关闭后允许多人共享、同人重复指定，每次分别扣次数、占槽位。重新开启不会清理已有共享关系。普通随机抽取仍排除已被持有角色。
- 赠送默认直接完成，可改为接收者确认。周期按配置时区和重置时间计算，默认北京时间每日 `00:00`。
- 格式错误、保护拒绝和额度不足不会开启新的通用冷却；接受、拒绝和取消赠送不受通用冷却约束。

</details>

### 列表与统计

| 关键词                                                    | 作用                                                                 |
| --------------------------------------------------------- | -------------------------------------------------------------------- |
| `老婆列表 [页码]` / `老公列表 [页码]` / `群友列表 [页码]` | 查看本群对应玩法的当前关系。                                         |
| `亲密度排行 [页码]`                                       | 默认查看本人对群友的累计亲密度，也可配置全群有向排行。               |
| `活跃度排行 [页码]`                                       | 查看统计窗口内的消息数和活跃天数，按消息数排序。                     |
| `查询好感度 @用户`                                        | 查询自己与一位当前合格的其他群友两个方向的累计分数，缺失方向为 `0`。 |

列表和排行默认每页 10 条。亲密度、活跃度和好感度默认只发图片，渲染失败降级文字；长排行按条数或图高分段，使用合并转发。统计卡片显示群名片（缺失时用昵称）和头像，不附 QQ 号；群友关系列表仍显示双方 QQ 号。头像失败时使用占位图。

<details>
<summary>活跃天数与统计窗口</summary>

活跃度默认统计近 7 天，窗口为滚动的 `N×24` 小时。活跃日期按群配置时区划分，因此可能跨越 `N+1` 个自然日期。

发送合格消息或主动戳一戳都计活跃日期，每人每天只计一次；被戳不计。主动戳机器人只增加活跃天数，不增加消息数或亲密度。旧消息可回算活跃日期，旧戳缺少发起者记录，无法回补。

</details>

### 管理员命令

| 斜杠指令                   | 权限与作用                                                    |
| -------------------------- | ------------------------------------------------------------- |
| `/设置老婆 <角色名或别名>` | 仅 Bot 管理员或全局额外命令管理员可用，为发送者设置今日老婆。 |

该命令精确匹配当前启用老婆池的角色名或别名，允许开头先 @ 机器人。它创建普通关系，不消耗普通或指定次数、补抽资格，也不受普通容量限制；允许不同用户持有同一角色，同一用户不能通过此命令重复持有。它与普通用户的指定抽取规则独立。

<a id="configuration"></a>

## 配置

AstrBot 原生插件配置页可编辑全部全局配置；管理页可编辑全局业务配置及群级覆盖。

- 宿主顶层 `enabled` 控制是否启动插件，关闭时不打开数据库。
- 原生页的 `settings.enabled` 是业务总开关，管理页中显示为 `enabled`。两者均开启才能使用玩法。
- 下表业务键以管理页及默认配置文件为准；在原生页中位于 `settings` 下，例如 `modes.wife.capacity` 对应 `settings.modes.wife.capacity`。

管理页选择「全局」或群后，修改字段、**校验草稿**、**保存配置**。群字段可在「继承全局」与「本群覆盖」间切换。保存失败或版本冲突会保留草稿，切换范围失败会保留原范围。保存成功后在后续群事件中生效，当前周期的重置安排按周期规则延续。

### 常用选项

| 配置键                                                                 | 默认值                               | 作用                                                  |
| ---------------------------------------------------------------------- | ------------------------------------ | ----------------------------------------------------- |
| `enabled`                                                              | `true`                               | 业务总开关，可按群暂停。                              |
| `modes.<mode>.enabled`                                                 | `true`                               | 分别启用老婆、老公、群友玩法。                        |
| `modes.<mode>.capacity`                                                | `1`                                  | 普通持有容量，范围 `1～100`，同时决定普通抽取总额度。 |
| `modes.wife.pool_ids` / `modes.husband.pool_ids`                       | `["wuwa_wife"]` / `["wuwa_husband"]` | 选用角色池；空列表表示无候选池。                      |
| `modes.wife.designated_capacity` / `modes.husband.designated_capacity` | `1`                                  | 指定次数与槽位上限，范围 `0～100`；`0` 关闭。         |
| `modes.wife.designated_unique` / `modes.husband.designated_unique`     | `true`                               | 指定时要求角色独占；关闭允许共享和重复指定。          |
| `reset.timezone` / `reset.time`                                        | `Asia/Shanghai` / `00:00`            | 每日周期的 IANA 时区和 `HH:mm` 重置时间。             |
| `commands.cooldown_seconds`                                            | `3`                                  | 通用冷却，范围 `0～86400` 秒；`0` 关闭。              |
| `statistics.activity_window_days`                                      | `7`                                  | 活跃度窗口，范围 `1～365` 天。                        |
| `display.pagination_enabled` / `display.page_size`                     | `true` / `10`                        | 列表和排行分页；关闭后返回全部，长排行按需分段。      |

`<mode>` 为 `wife`、`husband` 或 `member`。以上仅为常用项，完整配置见 [默认配置](./resources/default-config.json)与 [配置 schema](./_conf_schema.json)。全局资源限制、批量导入默认设置、历史保留、群准入规则和额外命令管理员只能全局配置。

### 回复文案、图片与引用

管理页可逐条修改操作结果、错误、通知、标题及统计标签。模板每条 `1～1000` 字符，允许变量由控件列出；未知变量、错误大括号或缺失必要变量会被校验拒绝。使用 `{{`、`}}` 输出字面大括号。

`{image}` 是图片占位符，例如将「已有老婆」回复改为：

```text
你今日已有{name}啦，不要太贪心哦。{image}
```

删除 `{image}` 即关闭该模板的附图；多图按顺序插入，重复占位符会重复插图。模板可仅写 `{image}`，没有可用图片时使用文字结果兜底。已有多段普通关系可用 `{names}`。旧版成功抽取模板升级时会补上 `{image}`，保留附图行为。

在「结果回复引用」「错误回复引用」中，分别设置每条回复是否引用触发消息，默认关闭，可按群覆盖。合并消息的引用放在首个转发节点；定时通知没有消息源时直接发送。已排入队列的通知保留入队时文案。

<a id="webui"></a>

## 管理页

在 AstrBot Dashboard 插件页面打开「今日姻缘」管理页。**所有已登录 Dashboard 的用户均可访问和操作**，不以 QQ 群管理员身份授权；图片读取、上传和数据接口也要求 Dashboard 登录。

| 分区 / 能力 | 操作                                                                         |
| ----------- | ---------------------------------------------------------------------------- |
| 配置管理    | 全局或群级配置、角色池开关、文案与引用设置、草稿校验和保存。                 |
| 角色目录    | 搜索、分页、新建与编辑角色和池；多图上传、缩略图及大图查看。删除前核对影响。 |
| 仓库同步    | 检查默认分支的角色与池，查看差异并选择同步；冲突默认不勾选，可明确覆盖。     |
| 数据查询    | 查询关系、配额、邀请、统计及操作记录；纠错先预检再提交。                     |
| 数据维护    | JSON/ZIP 角色包预检、导入和导出，完整备份及恢复预检。                        |

仓库同步默认勾选新增或无本地修改的项目；仓库移除的角色保留在本地，图片只追加。所选内容通过图片校验后整批提交。最多读取 1000 个配置文件，单个 JSON 响应、单文件及配置总量均限 50 MiB（52,428,800 字节）。

### 批量导入角色图

1. 在「角色目录」点击 **批量导入角色图**，选择图片或拖入选择区。支持 PNG、JPEG、WebP，每张最多 12 MiB、4000 万像素；批次默认最多 5000 条、200 MiB，总量由资源配置调整。上传阶段只保存暂存图片和草稿。
2. 选择默认男女池，按需修改检测关键词。可保存为全局默认或仅应用本批次；映射不会自动启用该池参与抽取。
3. 上传后检查匹配结果。已有角色只追加图片，不改名称、别名、性别、启用状态或卡池；未匹配项可关联已有角色或新建，名称和自动生成的 ID 均可修改。
4. 点击 **确认导入可靠项**，核对成功与失败列表，确认后进入人工处理阶段。
5. 调整歧义或未知性别项目，保存修正、勾选审核确认，再点击 **确认导入已审核项**。更改角色字段会撤销原审核；未填完整的草稿可以保存，但批准或提交前必须补全。

<details>
<summary>文件名匹配与失败处理</summary>

- 去除扩展名后，先按完整文件名匹配 ID，再匹配名称或别名；未命中时去除性别词和末尾图片序号再尝试。例如 `角色名_女_01.png`、`角色ID_男_02.webp`。匹配所有未删除角色，包括停用角色。
- 默认性别词为 `男、male` 与 `女、female`，英文不区分大小写，`female` 不会重复算作 `male`。男女关键词冲突或名称歧义需人工确认；未知性别暂按男标注。已有档案优先于文件名检测。
- 同名新图片默认关联同一个新角色草稿。图片按内容去重，同角色已有与新增图合计最多 20 张；超限时须人工跳过部分图片或更换目标，不会自动只导入前 20 张。
- 按角色独立提交，单个角色失败不阻断其他角色，成功项不会因后续失败撤销。失败文件保留原因，可跳过后重新上传。

</details>

关闭窗口会保存修正草稿，可通过 **恢复未完成批次** 继续。批次自创建起保留 24 小时，仅创建者可见；过期草稿与暂存文件会清理，已导入内容不受影响。未保存编辑遇到刷新或离开页面会提醒。

<details>
<summary>关系重置、每日数据重置与恢复</summary>

在「数据查询」按群和玩法选择操作，核对弹窗后执行，无需填写理由：

| 操作         | 当前周期内的影响                           |
| ------------ | ------------------------------------------ |
| 重置关系     | 结束活跃关系，不恢复每日额度、不发放补抽。 |
| 重置每日数据 | 清零每日抽取、偷取和离婚计数，不结束关系。 |

两者均保留历史、亲密度、活跃度、补抽资格和待处理赠送。关系重置后，绑定原关系的邀请在接收时提示失效。

完整恢复会覆盖当前插件数据，提交前自动建立当前备份。恢复后同步 AstrBot 全局配置；若提示“数据已恢复，但同步到 AstrBot 配置失败”，重试本次提交即可补同步，无需再次覆盖数据。重载也会优先使用恢复后的配置。

</details>

## 数据与安全

运行数据位于 AstrBot 的 `data/plugin_data/astrbot_plugin_daily_bonds/`，不写入源码目录：

```text
astrbot_plugin_daily_bonds/
├── state.sqlite3       # 配置、关系、用户与群数据、统计、邀请和操作记录
├── media/              # 角色图片
├── avatars/            # QQ 头像缓存
├── staging/            # 导入、恢复等暂存内容
└── backups/            # 完整备份
```

保存内容包括群成员缓存、QQ 号、消息计数、亲密度、活跃日期和管理操作记录。玩法关系按群与周期隔离，业务配置支持群级覆盖；历史保留和头像缓存期限可配置。

内置图片会从角色清单中的外部地址下载，头像向 QQ 头像服务请求，仓库同步访问 GitHub API 和原始文件地址。远程图片与 ZIP 导入执行来源、大小、路径、解码和摘要检查。

角色包导出包含目录与素材；完整备份还包含数据库及群和用户数据，请按包含个人数据的文件保管。通过管理页预检备份后恢复，迁移时核对作用域映射。重启或恢复后，未完成的确认赠送会标为失效或结果未知。

## 已知限制与常见问题

| 现象 / 条件                     | 行为与处理                                                                 |
| ------------------------------- | -------------------------------------------------------------------------- |
| 使用其他适配器或宿主低于 4.28.2 | 当前仅声明支持 aiocqhttp；请使用符合运行要求的环境。                       |
| 指令无回复                      | 检查插件加载、两个启用开关、群与用户准入，以及当前关键词和前缀设置。       |
| 提示没有可抽取对象              | 检查玩法池是否启用、角色状态与图片登记；娶群友还需检查成员名单和参与资格。 |
| 图片下载或渲染失败              | 可降级为文字；检查日志与图片来源网络，缺失角色素材可在管理页补传。         |
| 长排行使用合并转发              | 实际发送依赖 OneBot 端支持合并消息；可启用分页或减少每页条数。             |
| 发送图片宽或高超过 1600 像素    | 按比例缩小临时副本，保留完整画面，图库原图不变；排行也遵守此规则。         |
| 配置保存提示冲突                | 草稿保留；核对最新配置后重新编辑和提交。                                   |
| 批量导入部分失败                | 成功角色已导入，失败项保留原因；修正后处理失败项即可。                     |
| 仓库读取提示超限                | 检查配置文件数量及 50 MiB 限制，减少目录数量或体积后重新检查。             |
